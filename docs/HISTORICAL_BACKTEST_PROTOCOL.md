# Historical disturbance backtest protocol

This protocol answers a narrow question: **which parts of a past Road & Fire disturbance can CiviFlux reproduce or predict against evidence that it did not already ingest?** A historical event name, a real city map and a running SUMO job do not together establish historical accuracy. Run `python3 scripts/historical_backtest_preflight.py` from the repository root for the current evidence inventory; its report is a readiness check, not a validation score.

## Evidence levels and claim ceilings

| Level | Reference evidence needed | What is scored | Permitted claim |
| --- | --- | --- | --- |
| V1a — source transcription | Original dated event notice/report, archived URL or source ID, exact quoted fact spans or equivalent structured citations, timezone and uncertainty | Fact extraction completeness and contradiction count; `unknown` remains unknown | Source facts were transcribed correctly. A planned notice is not proof that a closure occurred. |
| V1b — physical reconstruction | Event-date road network and, for transit claims, event-date GTFS; reviewed directed-edge mapping, effective interval, vehicle permissions and entrance/stop matching | Correct reviewed fact-to-edge/time compilation and deterministic routing constraints | The declared historical restrictions were correctly represented **if their actual operation is independently established**. If only a later network is available, say *current-network what-if*. |
| V2 — independent operational impact | Event-date affected route/stop, closure, diversion, or service records from a source withheld from scenario construction | Detection/coverage of observed affected entities, with explicit candidate universe and missing labels | A bounded operational impact match. It is not measured travel-time accuracy or causation. |
| V3 — independent numeric outcome | Timestamped, geolocated event and comparable non-event observations of counts, speeds, travel times or delays, with units, coverage and collection method | Error and paired event-vs-control differences on previously frozen held-out observations | Numeric retrospective validity for the named outcome, location, time and data source. It does not generalize to other incidents without additional cases. |

The levels are **separate claims**, not a staircase that upgrades all outputs at once. A V2 transit diversion match does not verify hospital access time; a V3 detector speed comparison does not verify PPR as risk. Ontology and PPR outputs are semantic *attention/relevance*; physical outcomes must be checked using routing/SUMO and independent physical observations. The optional hosted SimpleJev classifier may reweight soft semantic relations, but it cannot set closures, speeds, demand, capacity, fire perimeters or observed labels. Historical checks of deterministic GIS and routing can proceed with zero model API calls.

## Freeze one historical backtest before observing its labels

1. **Register the event and question.** Record event ID; source IDs and archived snapshots; `Europe/Helsinki` local times plus UTC intervals; exact restriction geometry, direction and vehicle class; provenance `observed`/`announced`/`assumed`; unknown start/end bounds; network, GTFS, facility and demand snapshot SHA-256; permissible outcome types. Keep the actual incident and hypothetical restrictions as separate objects/Actions. A fire severity adjective never supplies a perimeter.
2. **Construct an event-date baseline.** Prefer pre-event OSM/GTFS archived snapshots that cover the event. Check GTFS service-day rules (including times after 24:00) and street changes. If historic bytes do not exist, run the current map only as a sensitivity/what-if analysis. Map every source road from reviewed landmarks to *directed* edges; retain unmapped/ambiguous facts in the denominator. A second reviewer should sign the mapping source, method and timestamp; a generated map is review material, not approval. Record network boundary alternatives and facility entrance confidence.
3. **Freeze inputs and targets separately.** Create an immutable run manifest with source byte hashes, ontology/projection versions, scenario/action-log hash, graph policy, software/SUMO versions, OD seed, measured-demand training inputs, evaluation windows, control selection and analysis code commit. Write a distinct held-out label manifest with its own hashes and access path. Inference and graph construction receive only the input allowlist. Affected routes, measured delays or sensor counts used as targets must never appear in prompts, KG facts, calibration, seed selection or selection of evaluation sites.
4. **Reconstruct each scenario with paired controls.** Hold city snapshot, OD demand, random seed, population, facilities and physics constant between baseline and event. The event arm changes only the independently evidenced restriction schedule. Report an additional explicitly hypothetical arm for uncertain times/geometry; never merge it with observed history. Compare direct GIS/routing (A0), typed KG rules (A1), fixed PPR (A2), and any authorized frozen SimpleJev policy under the same physical facts. Include no-restriction placebo, shifted date/time, unaffected corridor and relation-permutation controls. A negative control that produces a large effect requires investigation before any positive claim.
5. **Score only independently observed outcomes.** V1 counts source facts, mapped candidates, independently accepted matches, wrong-direction/time/permission violations and unknown fields. V2 evaluates a frozen candidate universe of route/stop/road/facility entities against independently archived changes; count positives, negatives, missing labels and unmatchable IDs separately. V3 aligns every detector/trip to location, direction, UTC interval and unit; describe coverage and missingness before reporting error. For the event effect, compare event-vs-baseline changes with matched same-weekday/control periods and unaffected locations; record weather, other works, holidays and demand shifts as possible confounders. A difference-in-differences estimate is descriptive unless its identification assumptions are defensible; it does not prove the model caused a real effect.
6. **Preserve the audit trail.** Save per-case metrics and denominators, raw prediction/label joins, failed joins, excluded observations with reasons, input/target hashes, command, environment, CI/test logs and uncertainty variants. Mark each claim `VERIFIED`, `PARTIAL`, `NOT_VALIDATED`, or `BLOCKED_SOURCE` with the exact missing evidence. Do not promote an engineering PASS to a scientific validation PASS.

## Metric definitions and uncertainty

- **V1:** use `accepted directed restrictions / source motor-road restrictions`, plus separate candidate coverage, wrong direction count, interval precision, vehicle-class unknown count and signed reviewer count. If a source fact lacks hours, no minute-level correctness denominator can be formed. For R1, Baana walking/cycling timing must not be copied onto motor roads.
- **V2:** choose the universe *before* inspecting targets. Report `TP`, `FP`, `FN`, `TN`, unknown/unmatched count, precision `TP/(TP+FP)`, recall `TP/(TP+FN)` and `Recall@K` only where denominators are nonzero and labels are genuinely independent. Include entity-type strata and whether a route was directly restricted, rerouted, or merely ranked as relevant. An unlabeled entity is not a negative.
- **V3:** for matched sensor/route/time cells report `n_observed`, `n_matched`, `n_missing`, MAE and signed bias for the pre-registered physical quantity and unit; count/flow, speed, delay and travel time remain distinct. Report baseline/event paired difference, uncertainty interval or event-level descriptive range, and control-period difference with matching diagnostics. Censored unfinished SUMO trips and unavailable detector intervals remain visible, not discarded to improve mean delay.
- **Robustness:** vary reasonable closure-time bounds, source-to-edge mapping, current vs archived network, outer network boundary, facility snap and demand calibration **one assumption at a time**. Preserve each assumption's provenance. If rank or route conclusions change materially, report instability instead of selecting a convenient version.

For train/dev/test, split by **event or corridor family and date**, not by near-duplicate parameter variants. Tune route, demand and semantic-policy hyperparameters on train/dev only. Freeze one test manifest and run it once; subsequent corrections create a new version with the original failures retained. Two Helsinki examples are a demonstration of the audit method, not a sample for city-wide statistical generalization. The public repository should publish derived audit tables only where each source licence and privacy rule allows it; it should not mirror restricted raw feeds or disclose individual movement traces.

## What closes today's gaps

R1 first needs an independent human review of each notice-to-directed-edge mapping and an archived record that confirms actual operated intervals/classes. Event-date OSM/GTFS would support historical topology/transit reconstruction. Independent HSL operations records would permit a V2 affected-service test only if withheld from inference. Event-matched detectors or transit travel-time observations plus comparable controls would permit V3 for those specific observables. F1 additionally needs independently sourced exact location/actual cordon or diversion; without those, its current assumed closure remains a what-if even if a traffic time series appears later. Source access, cost and rights must be checked when those records are actually found; their mere existence cannot be inferred from a data portal listing.
